# 实验辅导 Agent 回归案例

这些案例来自实际反馈。用于验收程序行为和回答质量，不把“工具测试通过”写成“Qwen 效果已达标”。

## 分层与状态

- A：pytest + SQLite + FakeProvider。检查编号解析、预取、工具数据、隔离与预算。已有可执行测试见下表。
- B：Playwright + TutorTestProvider。检查界面/接口；不代表 Qwen 会自己查询或正确解释。
- C：真实百炼 Qwen。检查自由提问的工具选择、多轮纠正、证据引用和结论。2026-10-15 已使用合成实验记录、临时 SQLite 执行部分案例；具体范围、失败项和用量见 `AGENT-EVIDENCE-VALIDATION.md`，不能视为整表通过。
- D：真实课堂试点。衡量学生是否能理解并完成任务，单纯回答正确不能证明教学效果。

## 可重复测试场景

在独立测试项目中按时间创建第 1–5 次记录；第 2 次 SGD/0.001，第 3 次 SGD/0.001，第 4 次 SGD/0.1。对照组保持数据版本、划分、种子、批大小、轮数、骨干一致；另设一个更换优化器或划分的负对照。页面选中第 4 次，列表按新到旧显示。

这是一组验收夹具要求，不是用户现有项目的事实。优先复用 `test_agent_numbering.py::seed_runs`；其合成指标不用于证明学习率优劣。

| 编号 | 问题/操作 | 必须观察到的行为 | 已有 A 层覆盖 / C 层要求 |
| --- | --- | --- | --- |
| R01 | “分析一下第五次实验的曲线图”及中文/全角数字 | 读取第 5 次、include_curve=true，不能替换为当前选中记录，不向学生索要内部 ID | `test_numbered_curve_is_prefetched_without_model_tool_decision`；C 检查回复引用曲线数值 |
| R02 | 上述问题后连续追问“第5次”“第五次” | 保留曲线意图并定位同一记录 | `test_repeated_bare_number_retains_curve_intent`、`test_bare_number_continues_curve_question_and_old_record_is_resolvable` |
| R03 | 仅有 2 次记录却问第 5 次 | 明确不存在，并说明已有数量；不编造或代用记录 | `test_missing_ordinal_never_falls_back_to_current_run` |
| R04 | “对比第二次和第四次实验” | 读取两条记录并比较参数，包含学习率变化；不能只比较末轮准确率 | `test_explicit_pair_prefetches_comparison`；C 检查完整参数和结论边界 |
| R05 | 先问“学习率0.1和0.001哪个好”，再纠正“第三次用的也是SGD” | 主动查询第三次与当前第四次，更新依据，不继续坚持旧笔记中的 AdamW | `test_parameter_correction_continues_current_comparison`；C 检查回答确实纠正错误 |
| R06 | 未给编号，仅问“0.1和之前0.001哪个好” | 先查询索引/记录；有多个候选时给出编号和参数帮助选择，不能把“没查”说成“工具没有数据” | 暂无专门确定性覆盖；C 必测，不宣称已解决所有自由表达 |
| R07 | 两次数据版本或划分不同 | 明确比较限制，不把效果差异全归因于学习率 | `test_agent_evidence.py` 覆盖同数量不同划分、元数据缺失、参数不全、种子/多参数变化；C 检查模型确实遵守限制 |
| R08 | “第五轮训练的损失是什么意思”“为什么之前没分析第5次曲线” | 区分轮数、操作请求、质疑历史行为，不能机械触发编号预取 | `test_ambiguous_or_meta_questions_are_not_force_routed` |
| R09 | 高验证准确率、很小验证集 | 结论限定于当前实验条件，不能宣称统计显著/已证明泛化；建议同一独立测试集 | C 人工评分，FakeProvider 不评价教学语言 |
| R10 | 多轮追问相同实验 | 查看调用证据和累计 token，检查重复曲线/重复调用；不编造逐轮成本 | `test_idempotency_budget_and_summary` 仅覆盖请求幂等/预算；尚无逐轮 token 明细与完整去重验收 |
| R11 | 切换项目，引用另一项目记录 | 不能读取其他项目实验、对话或笔记 | `test_ownership_and_cross_project_conversation`、`test_index_pagination_and_number_details_are_consistent` |
| R12 | 切换基础/进阶；无正确标签的测试结果 | 只生成当前一种深度；不把预测分数当实际准确率，不看照片却推断背景 | `test_fixed_next_and_mode_use_real_project_data`、`test_tools_comparison_and_stale_camera_state` 部分覆盖；C 检查解释 |
| R13 | 首末轮准确率 100%，中间降至 60%；末轮损失恰为最小值 | 说明中途下降/反弹，不能声称全程 100% 或无反弹；不凭曲线确定原因 | `test_final_minimum_does_not_hide_intermediate_rebound`；C 使用第 15–17 轮异常的 30 轮夹具 |
| R14 | 模型返回 `run_number: "4"` | 仅接受规范正整数字符串；布尔、浮点、表达式与其他字段仍严格校验；项目隔离不变 | `test_string_run_number_is_narrowly_normalized_without_mutation`、`test_realistic_string_tool_call_succeeds_without_error_retry` 等 |
| R15 | 请求中间权重、早停、正则化或切换旧模型 | 说明功能未提供；建议修改轮数重新训练；区分分析记录与实际校验模型 | `test_product_limits_and_active_prediction_model_are_in_context`；C 检查不存在的操作入口 |

本轮按用户要求不修改 `agent_context.py` 的比较意图识别。R05/R06 的自由措辞仍属后续工作；不能把显式“对比第二次和第四次”通过写成所有学习率问法均通过。

## 真实 Qwen 验收方式（另行授权后执行）

使用独立测试项目与测试数据库，记录模型标识、代码提交、讲解模式、夹具参数和时间。密钥由用户在本机配置，不进入记录或报告。

关键 R01/R04/R05/R06/R09 各运行至少 3 次新对话；R02/R05/R10 保留多轮上下文。记录实际工具名、参数、返回记录编号、回答数值、结论边界、错误与总 token。3 次只是初步稳定性检查，不是统计可靠性证明。

每项分别判定：取对数据 / 解释符合数据 / 学生可操作 / 不越界。工具调用成功不等于回答通过。若缺少逐轮用量日志，只报告总量，不能推算重复调用各自花费。

记录模板：

| 案例 | 代码提交/模型/模式 | 重复次数 | 数据与参数 | 工具证据 | 结论是否有据 | tokens/耗时 | 结果与问题 |

| Rxx | 待填 | 待填 | 使用合成测试记录，不填凭据 | 待填 | 待填 | 待填 | 未执行 |

## 日常使用

对 Codex 说：“按 AGENTS.md 修改实验助手，复用 R04/R05 回归案例，运行隔离测试，区分模拟测试和真实 Qwen 验证，不自动提交。”

发现新问题先保存最短复现对话及必要实验参数，再决定补程序测试、真实模型验收或两者。不要复制包含学生身份、真实密钥或完整图片的数据。

## 样本检查漏查回归（2026-10-15）

用户原话：“帮我检查样本分布，并说明下一步怎么做。”这是前端“帮我检查样本”预填的普通提问。

- 50/50、5/50、0/0：先回答各类真实数量与总数，再给出符合当前阶段的步骤；数量均衡不证明图片质量，数量不均只提示风险。
- 即使模型没有调用工具，首轮上下文也必须有本次授权项目的 `experimentState`；修改样本后下一次问答必须刷新，不依赖旧对话中的数量。不得携带图片内容。
- 没有独立“样本”页签、划分浏览器或数据增强设置。操作应指向左侧“准备样本”中的“上传图片”/“摄像头”；每类 5 张只是最低运行要求，不能编造每类 30 张合格线。
- 自动回归：`test_sample_distribution_is_counted_without_quality_claims`（含空类、相等、不等、零分母）及 `test_sample_question_has_fresh_counts_even_when_model_does_not_call_tools`。原有比较意图路由未改。
- 真实复测及局限见 `AGENT-EVIDENCE-VALIDATION.md` 的样本检查补充记录。

## 误分类先澄清回归（2026-10-15）

- 单独问“为什么输出结果是错的”：只问实际类别，不查最近测试、不罗列原因。
- 回复“实际是猫”：只追问当时预测成什么；回复“识别成狗”：承接这条反馈继续分析，不重复询问实际类别。
- 一次说清“实际是猫，却识别成狗”：直接进入证据分析；“兔子被识别成猫”且项目只有猫狗时，解释分类范围。
- 换图/换对象后再次报错：视为新的反馈，不沿用上一张的真实类别或预测结果。
- 摄像头错误不得与最新文件测试匹配；明确实验编号的报错也不先自动预取曲线，留给澄清后按需查询。
- 程序测试覆盖编号预取延后、补齐反馈后工具仍可用、文件历史声明不包含摄像头且未匹配事件；语义理解与是否重复追问使用真实模型验收，不能由 FakeProvider 测试代替。
